# 影之刃零：伤害测试木桩

[![Build and release](https://github.com/xbunax/pbz_damage_test/actions/workflows/release.yml/badge.svg)](https://github.com/xbunax/pbz_damage_test/actions/workflows/release.yml)

通过游戏内菜单召唤一个独立训练目标，用于测试攻击和连招的生命伤害。当前为预览版，训练目标使用游戏自带的金面人训练资产，外观是人形。

## v0.1.0-preview.3：训练设置、分段 DPS 与双语菜单

### 中英文菜单

F8 → “训练设置 / Training”页顶部 → “菜单语言 / Language”，可选择“简体中文”或“English”。选择后立即刷新界面，不需重启游戏；偏好保存在实际 Mod 根目录的 `ui_language.txt`，更新和重启后保留。首次使用默认简体中文。无法写入偏好时保留原语言并显示原因。

翻译覆盖菜单标题、分页、按钮、说明、目标分类与名称、原生红蓝模式、攻击恢复状态、DPS 暂停和分段对比提示。切换保留现有木桩、伤害数据、暂停状态、目标选项及未提交的输入；用户填写的武器名和备注不翻译。旧分段通过稳定的目标 ID 显示当前语言的目标名称，保存数据本身不改写。英文目标名和分类是本 Mod 的说明性译名，不声称为游戏官方英语本地化。

已加入切换保留状态、翻译覆盖、中文自定义名称保留、偏好读写和失败回退的离线检查；游戏内布局、鼠标交互和英文长文本换行仍需实机验收。

### DPS 暂停与武器分段对比

F8 菜单的“伤害统计”页新增“暂停统计 / 继续统计”和“保存本段，下一段保持暂停”，新增“分段对比”页。武器名或备注由玩家手动填写，留空自动编号。

1. 用第一把武器攻击目标；首次有效命中开始计时。停手仍计时，需要结束测量时点击“暂停统计”。
2. 填写武器名或备注，点击保存。也可直接保存，保存时自动暂停；成功后清空当前统计，下一段保持暂停，方便换武器。
3. 换好武器后点击“继续统计”，下一次命中开始新段计时。重复保存后，在“分段对比”页选择 A 基准和 B 对比。

暂停期间，计时、伤害、命中、最高单次与回血次数均冻结；木桩仍正常受击和自动回血。继续后扣除暂停时长，近 5 秒 DPS 也使用同一有效时间轴。暂停只控制本 Mod 统计，不暂停游戏。打开 F8 菜单仍会停止循环攻击，统计需手动暂停。

每段保存目标、血量、训练模式、总伤害、有效时间、命中数、最高伤害、回血次数和平均 DPS。对比页显示两段数据与 B 相比 A 的 DPS 差值及百分比，目标、血量或训练模式不一致会提示。武器名不自动识别；其他装备、增益、防御状态等仍需自行保持一致。平均 DPS 仍按最短 1 秒计算。

历史保存在实际 Mod 目录的 `PBZTrainingDummy/dps_segments.json`，重启后保留，最多 100 段，可在对比页删除 B 选中的记录。写入前验证临时文件并备份上一版；保存失败保留本轮统计供重试。文件损坏时尝试读取 `.bak`，无法恢复则禁止覆盖并显示原因。未点击保存的本轮数据不会跨重启保留。更换目标、重新召唤、调整血量和重置均不删除历史分段。

新增暂停计时、连续暂停恢复、保存/读取/删除、写入失败保留、损坏恢复、容量上限及菜单联动的离线测试；当前版本的按钮操作、中文名称输入和重启后读取仍需实机验收。

### 分类选择与受击恢复

目标选择改为两级：先选“图鉴分类”，再从该类中选择小怪，第二级支持搜索。共 25 个训练目标：独立金面人训练木桩 1 个、怪面 12 个、龙体改造 7 个、人偶 4 个、动物 1 个。包含黄袍暴徒、大盾/刀盾暴徒、双斧暴徒、疯妇、双镐疯妇、山贼、无面剑客/枪兵及其队长、白山女徒、鬼差、四种人偶和狂犬。

分类依照原生图鉴 `FCodexEnemyRow.EnemyType`，并以独立的 `bIsBoss` 字段排除 Boss。中文分类标题是原生枚举的说明性译名，未作为官方本地化原文认证；图鉴未给出的小兵/精英等级不自行推断。`HumanMaster` 类目前未加入普通目标，因此不显示空分类。新增目标仍属预览，未逐个完成游戏内验收；缺少统计被动或初始化失败时会显示原因。

- 完美闪避反击、受击或冷却导致激活被拒绝时，每 0.5 秒等待恢复再试，持续 30 秒无法恢复才停止。技能执行仍有超时保护，打开菜单仍立即停止循环。
- 目标选项明确标注红光、蓝光或静止受击；持枪保留原生红光，持剑、黄袍和双镐开放已核对的原生蓝光。其余新增角色先支持静止受击，红蓝招式待核验，不跨角色移植。
- 修复重新开启仇恨的 Blueprint 输出参数转换；修复受击后行动效果句柄失效导致无法重新开始循环的问题。

### 训练设置与 DPS

F8 菜单新增“训练设置”和“伤害统计”两页：

- **目标选择**：金面人训练木桩、持枪暴徒、持剑暴徒；切换类型会移除旧目标，再点击召唤。Boss 尚未接入。
- **目标血量**：默认 10000，可设为 10～10000000 的整数。点击“应用血量并重置统计”后回满血并清零本轮统计；新召唤也使用该设置。
- **关闭木桩仇恨**：默认开启，处理训练目标与玩家之间的仇恨，不清空玩家与其他敌人的关系。关闭此选项会恢复木桩对玩家的仇恨。
- **循环攻击（实验）**：持枪暴徒显示红光模式，持剑暴徒显示蓝光模式；金面人只提供静止受击。设置攻击结束后的间隔（0.5～30 秒），点击开始。打开 F8 菜单会停止攻击；玩家死亡、换图或切换目标会清理木桩。
- **平均 DPS**：累计生命伤害 ÷ 首次命中后经过的游戏时间，最短按 1 秒计算。停手仍计时，移除目标后冻结结果；重置或重新召唤会清零。
- **近 5 秒 DPS**：最近 5 秒内的生命伤害 ÷ 5；停手满 5 秒后归零。另显示最高单次伤害、本轮时长、命中和回血次数。

训练设置在本次游戏内保留，重启后恢复默认；快捷键仍通过 config.ini 保存。持枪/持剑及红蓝技能使用实际游戏资产，攻击启动会核对技能是否已授予；拒绝激活、未观察到执行或执行超时会停止循环。角色的受击、防御、抗性仍影响测得伤害。

验证边界：本版已加入菜单、统计与攻击调度的离线回归检查；金面人关闭仇恨的早期原型经过用户实测。新版本的完整菜单、两种小怪、红蓝预警与防御判定仍需游戏内验收，离线通过不代表全部实机兼容。以下固定金面人/10000 血描述为默认静止模式的基础行为。

- 默认 **F8** 打开 / 关闭菜单，可修改按键映射。
- 菜单中召唤、重新召唤到面前、移除目标、重置测试。
- 目标不主动攻击，生命值为 **10000**；降至 **1 血**后自动回满，累计伤害继续保留。
- 显示最近一次伤害、累计伤害、命中次数、自动回满次数。多段攻击按伤害事件分别统计。
- 从游戏的伤害数据读取完整生命伤害，包括超出剩余生命的部分；架势、怒气伤害和攻击者资源回复不混入生命伤害。
- 排除木桩触发的战斗音乐，正常敌人的音乐触发仍由游戏处理。
- 同时只保留一个目标，切换世界或玩家角色时清理；不把木桩写入存档。

## 下载与安装包

从 [Releases](https://github.com/xbunax/pbz_damage_test/releases) 下载 ZIP，不要把源码 ZIP 当作 UE4SS 整合包。

| 文件名包含 | 适用情况 | 包含内容 |
| --- | --- | --- |
| `mod-only-windows-x64.zip` | 已经有正常工作的 UE4SS，包括已安装其他 UE4SS Mod | 木桩运行 Lua、配置、私有 UI/辅助库和许可证 |
| `with-UE4SS-windows-x64.zip` | 尚未安装 UE4SS 或其他代理加载器 | 木桩 Mod、锁定版本的 PBZ 专用 UE4SS、上游 `dwmapi.dll`、配置和签名 |

两个包包含相同的木桩代码，均不包含 PBZHitEnhance / UnifiedHitstop 的代码、面板或启动组件。木桩整合包可单独安装运行，不需要卡肉 Mod；两者的独立整合包不能覆盖叠装。**已有 UE4SS 时使用 mod-only，不要再装一套运行库。**

安装包遵循最小文件原则：只包含运行必需的 Lua、配置、加载器依赖及许可证；不放入 README、docs、Word/PDF、维护脚本、测试、个人数据或包内构建清单。安装与兼容说明在本仓库和 Release 页面阅读。完整 ZIP 的 `SHA256SUMS.txt` 作为独立 Release 附件提供。

## 安装 mod-only：已有 UE4SS

1. 完全退出游戏，备份现有 Mod 配置。
2. 找到**当前实际加载的 UE4SS** 所使用的 `Mods` 目录。不要仅凭游戏目录里有一个同名文件夹就判断位置。
3. 将 ZIP 中的整个 `PBZTrainingDummy` 文件夹复制到该 `Mods` 目录：

   ```text
   <实际 Mods 目录>/
   ├─ PBZTrainingDummy/
   │  ├─ config.ini
   │  ├─ Scripts/
   │  │  ├─ main.lua
   │  │  ├─ runtime.lua
   │  │  └─ vendor/...
   │  └─ licenses/...
   └─ mods.txt
   ```

4. 在 UE4SS **实际使用的控制列表**中新增或启用这一行，保留其他 Mod 的条目：

   ```text
   PBZTrainingDummy : 1
   ```

5. 启动游戏，进入可自由行动的场景后按 F8。

如果使用 `Overrides.ModsFolderPath`、`Overrides.ControllingModsTxt`、`mods.json` 或外置运行库，以现有加载器配置为准；只通过一种控制方式启用本 Mod。不要用发行包中的 `mods.txt` 覆盖已有列表。Mod 不修改共享 UE4SS 设置；请核对[所需 API 与 Hook 设置](docs/COMPATIBILITY.md#所需接口与设置)。

若继续使用旧卡肉运行库：日志中的 `unsupported_game_skipped` 是旧 PBZHitEnhance 加载器的拦截，木桩 mod-only 无法修复该代理；应单独升级 [PBZHitEnhance v0.4.0-preview.3](https://github.com/xbunax/pbz_hit_enhance/releases/tag/v0.4.0-preview.3)。这属于旧环境的迁移说明，不是独立木桩的依赖。

## 安装 with-UE4SS：尚未安装运行库

1. 完全退出游戏，确认目标位置没有其他 UE4SS 或代理加载器。若已存在 `ue4ss`、`UE4SS.dll`、其他来源的 `dwmapi.dll`，或通过 `dxgi.dll` / `version.dll` / `dinput8.dll` 等加载其他 Mod，先使用原加载器的安装说明确认用途，优先改用 mod-only。
2. 在 Steam 中浏览游戏本地文件，找到 `PBZ.exe` 所在的目录。本次实测布局为 `<游戏目录>/platform/steam/PBZ.exe`。
3. 将 ZIP 中的 **`dwmapi.dll` 和整个 `ue4ss` 文件夹**复制到 `PBZ.exe` 旁边，结构如下：

   ```text
   <PBZ.exe 所在目录>/
   ├─ PBZ.exe
   ├─ dwmapi.dll
   └─ ue4ss/
      ├─ UE4SS.dll
      ├─ UE4SS-settings.ini
      ├─ UE4SS_Signatures/...
      ├─ UE4SS_SDK_Backends/...
      └─ Mods/
         ├─ mods.txt
         └─ PBZTrainingDummy/...
   ```

4. 通过 Steam 正常启动游戏，进入场景后按 F8。不要再同时复制其他 UE4SS 加载器。

整合包直接使用校验过的上游 PBZ 专用代理和 UE4SS，不包含其他 Mod、调节面板或本机绝对路径。上游加载器与本项目的安装组合仍应按预览版进行验证；游戏内功能验证使用的是同一 UE4SS DLL，配合已有加载器完成。

## 从旧卡肉运行库迁移为独立木桩

适用于原来将木桩装在 PBZHitEnhance / UnifiedHitstop 外置运行库中、现在希望木桩单独运行的情况。完成此切换后，旧卡肉加载器及其外置目录中的其他 Mod 不会自动随新木桩安装加载。

1. 完全退出游戏和卡肉面板。打开 `PBZ.exe` 旁原有的 `PBZHitEnhance.ini`，查看 `[Paths]` 中的 `DataDirectory`；备份该目录中的木桩 `ue4ss/Mods/PBZTrainingDummy/config.ini`。若原运行库另设了 Mods 路径，以其实际配置为准。
2. 确认原 `dwmapi.dll` 属于 PBZHitEnhance 后，将该 DLL 和 `PBZHitEnhance.ini` 一起移到**游戏目录外的备份目录**。保留原外置数据目录及配置，不删除其他 Mod。若无法确认现有代理的来源，先按它所属项目的说明处理。
3. 按上方 with-UE4SS 步骤，将木桩包的 `dwmapi.dll` 和整个 `ue4ss` 文件夹复制到真实 `PBZ.exe` 旁。若那里已经存在另一套 UE4SS，先确认并按原说明停用或迁移，不直接混合覆盖。
4. 将备份的木桩按键配置恢复到新目录 `ue4ss/Mods/PBZTrainingDummy/config.ini`，确认新目录 `ue4ss/Mods/mods.txt` 中有 `PBZTrainingDummy : 1`。
5. 从 Steam 正常启动游戏，进入可自由行动的场景后按 F8（或配置中的映射键）。检查**新目录**中的 `ue4ss/UE4SS.log` 是否有 `[PBZTrainingDummy] loaded`，不要继续查看旧外置目录的历史日志。

此后木桩使用自己的安装目录和上游 UE4SS 加载器，不需要 `PBZHitEnhance.ini`、`PBZBootstrap.dll` 或卡肉面板。新版游戏的独立整合包冷启动尚未完成实测，当前已验证的 F8 恢复来自修复后的原运行库环境。

## 使用与按键映射

1. 在平坦、前方留有空间的位置打开菜单，点击“召唤木桩”，等待约 1 秒显示“木桩已就绪”。
2. 关闭菜单后攻击目标，再打开菜单查看统计。关闭菜单会保留木桩。
3. “重置测试并回满血”清空统计；“移除木桩”移除目标并保留当前统计。重新召唤会开始新一轮统计。

只开放菜单开关键的映射。退出游戏后编辑 `PBZTrainingDummy/config.ini`：

```ini
[Keybinds]
MenuToggle = F9
```

默认是 `F8`；可改为当前 UE4SS `Key` 枚举支持的键名，例如 `F9`、`F10`、`INSERT`、`P`。**修改后重启游戏生效**。Esc 固定用于关闭菜单；Esc 和鼠标按键不能映射为菜单开关键。无效值会记录日志并回退 F8。请选择没有被其他 Mod 或游戏动作占用的按键。

## 卸载与更新

- **mod-only：**退出游戏，把 `PBZTrainingDummy` 文件夹移出实际 Mods 目录，并将控制列表中的本项改为 `PBZTrainingDummy : 0` 或删除本项。保留 UE4SS 和其他 Mod。
- **with-UE4SS：**可以先按上面的方法只停用木桩。若要移除运行库，仅在确认 `dwmapi.dll` 和 `ue4ss` 属于这次整合安装、且没有其他 Mod 依赖时，将它们移出游戏目录；不要移除其他来源的文件。
- **更新：**已有运行库能正常加载时，退出游戏，备份 `config.ini`、`ui_language.txt`、`dps_segments.json` 及其 `.bak`，用新版本 mod-only 更新本 Mod 文件后恢复配置与分段记录。安装包不包含个人分段数据或语言偏好。若运行库本身未加载，先按上方对应步骤修复旧加载器或迁移为独立安装。

## 已知边界与故障排查

## 源码与构建发布

```text
PBZTrainingDummy/Scripts/   正式代码、独立的私有 UI/UEHelpers
tests/                     统计、伤害筛选、音乐隔离、按键与 API 检查
tools/                     Lua 编译检查、打包、安装包校验
docs/                      兼容性与版本说明
.github/workflows/         GitHub Actions 构建及发布
```

需要 Python 3.10+ 和 Lua 5.4 / luac；构建脚本本身只使用 Python 标准库：

```bash
python tools/validate.py
python -m unittest discover -s tests -p 'test_*.py'
python tools/build.py
python tools/verify_packages.py
```

在源码仓库中运行上述命令。构建会下载 `dependencies.json` 锁定的 UE4SS 归档并校验归档与 DLL 哈希。已有归档可传 `--ue4ss-archive <zip>`。产物在 `dist/`。Lua 源码会先经过 `luac -p` 编译检查，发行包保留 Lua 源码，避免跨 Lua/UE4SS 版本的字节码问题。构建工具、维护脚本和开发依赖清单不随安装 ZIP 分发。

Actions 在 main 推送、PR 和手动运行时验证并构建；只有 main 分支的成功运行能够发布。修改 `VERSION` 后推送 main，流程全部通过才创建对应版本的 Release，上传两个 ZIP 和校验文件。预览版本发布为 prerelease；已存在的版本不会覆盖。CI 不运行游戏，不代替游戏内验证。
